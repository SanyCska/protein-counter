# Деплой (Docker + GitHub Actions)

После пуша в ветку `main` workflow **Deploy** собирает образ на сервере и перезапускает контейнер. Ручной запуск: **Actions → Deploy → Run workflow**.

## Сервер

- Ubuntu (или другой Linux) с **Docker** и плагином **Docker Compose v2** — команда **`docker compose`** (два слова). Старый бинарник **`docker-compose`** (с дефисом) не используется.
- Открытый SSH (по умолчанию порт **22**).
- Пользователь с правом запускать `docker` (часто в группе `docker`).

Первый раз создай каталог деплоя (или он создастся сам из workflow через `mkdir -p`).

На сервер добавь **публичный** SSH-ключ, для **приватного** ключа из секрета `SSH_PRIVATE_KEY` (см. ниже).

## Секреты в GitHub (Settings → Secrets and variables → Actions)

### Обязательные

| Секрет | Описание |
|--------|----------|
| `SSH_HOST` | IP или домен сервера (например `203.0.113.10` или `bot.example.com`) |
| `SSH_USER` | Пользователь SSH (например `deploy` или `ubuntu`) |
| `SSH_PRIVATE_KEY` | Содержимое **приватного** ключа OpenSSH (весь файл `id_ed25519`, включая `BEGIN` / `END`) |
| `DEPLOY_PATH` | Абсолютный путь на сервере без завершающего `/` (например `/opt/protein-counter`) |
| `TELEGRAM_BOT_TOKEN` | Токен бота от [@BotFather](https://t.me/BotFather) |

### Рекомендуемые

| Секрет | Описание |
|--------|----------|
| `OPENAI_API_KEY` | Ключ OpenAI для режима «Посчитать с ИИ». Можно оставить пустым, если ИИ не нужен |
| `WEBAPP_URL` | HTTPS-адрес мини-аппа, например `https://109-71-246-174.sslip.io`. Без него бот работает как раньше, просто без кнопки, а TLS-прокси и фронт не поднимаются |

### Опциональные

| Секрет | Описание |
|--------|----------|
| `OPENAI_MODEL` | Модель (по умолчанию в коде `gpt-4o-mini`) |
| `TZ` | Часовой пояс для «сегодня» (IANA, например `Europe/Moscow`) |
| `SSH_PORT` | Порт SSH, если не **22**. Если секрет не задан, используется **22** |
| `WEBAPP_ORIGINS` | Origin'ы, которым API разрешает запросы. Обычно не нужен: если пуст, берётся `WEBAPP_URL` |

## Мини-апп

`docker compose` поднимает из одного образа `bot` (polling) и `api` (uvicorn на 8000),
плюс `caddy` для TLS и `web` со статикой фронта. База — общий volume `bot-data`,
так что блюда из бота сразу видны в мини-аппе.

### Адрес без покупки домена

Telegram открывает Mini App только по https, а сертификат Let's Encrypt не выдаётся
на голый IP. Обходится через **sslip.io**: имя `109-71-246-174.sslip.io` — это IP
сервера, записанный через дефисы, и sslip.io резолвит его в сам IP. Регистрировать
и оплачивать ничего не нужно, сертификат Caddy получает и продлевает сам.

Отсюда значение секрета: `WEBAPP_URL=https://109-71-246-174.sslip.io`. Из него деплой
выводит `MINIAPP_HOST` для Caddy, так что адрес живёт в одном месте. Переезд на свой
домен потом — A-запись на сервер и новое значение `WEBAPP_URL`, править конфиги не надо.

Требования к серверу: свободные порты **80 и 443** (80 нужен для редиректа и выдачи
сертификата) и доступность их из интернета.

### Кто чем владеет

| репозиторий | что делает |
|---|---|
| `protein_counter` | владеет стеком: rsync'ит файлы в `DEPLOY_PATH`, пишет `.env` из секретов, поднимает `bot`, `api`, `caddy` |
| `protein_web` | собирает образ фронта, публикует в GHCR и перезапускает только контейнер `web`; требует, чтобы стек хотя бы раз был задеплоен из бэкенда |

Фронт и API живут на одном origin: Caddy отдаёт `/api/*` в `api:8000`, остальное — в `web:80`.
Поэтому CORS фактически не используется, а `VITE_API_BASE` менять не нужно.

### Порядок первого запуска

1. Завести в **protein_counter** секрет `WEBAPP_URL` (и `TZ`, если ещё не задан).
2. Влить ветку в `main` — деплой поднимет `bot`, `api` и `caddy`. Пока фронта нет,
   Caddy отдаёт 502, это ожидаемо.
3. Завести в **protein_web** секреты `SSH_HOST`, `SSH_USER`, `SSH_PRIVATE_KEY`,
   `DEPLOY_PATH` (и `SSH_PORT`, если не 22) — те же значения, что у бэкенда.
4. Запушить `protein_web` в `main` — соберётся образ и поднимется `web`.
5. Открыть бота: кнопку меню и команду `/app` он проставит сам при старте.

### Порты на сервере

| порт | кто |
|---|---|
| 80, 443 | caddy — единственное, что торчит наружу |
| 127.0.0.1:8000 | api, для дебага по SSH |

### Дебаг

```bash
ssh <сервер>
cd <DEPLOY_PATH>
docker compose ps
docker compose logs --tail=100 api bot caddy web
curl -s http://127.0.0.1:8000/api/health   # api напрямую, минуя caddy
```

Если страница не открывается, первым делом смотреть `docker compose logs caddy` —
там видно, выдался ли сертификат.

## Локальный запуск в Docker

```bash
cp env.example .env
# заполни TELEGRAM_BOT_TOKEN и при необходимости OPENAI_API_KEY
docker compose up -d --build
```

База SQLite хранится в Docker volume `bot-data`.

## Ручной деплой

В репозитории: **Actions** → выбери workflow **Deploy** → **Run workflow** → ветка `main` → **Run workflow**.
