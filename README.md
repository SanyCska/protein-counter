# protein_counter — бот и API дневника питания

Телеграм-бот для быстрого учёта еды (текст или фото → ИИ считает КБЖУ) плюс HTTP API,
на котором работает мини-апп [protein_web](https://github.com/SanyCska/protein_web).

Бот и API живут в одном репозитории и работают с **одной SQLite-базой**: блюдо, скинутое
в бот, сразу видно в мини-аппе, а правки из мини-аппа видны боту.

## Что умеет

**Бот** — быстрый ввод: `/add` (вручную или через ИИ, с фото или без), `/today`, сохранённые
продукты, `/app` открывает мини-апп.

**API** — всё остальное: дневная норма, микронутриенты, физнагрузка, добавки, отчёты и графики.

## Запуск локально

```bash
uv venv --python 3.12 .venv && uv pip install --python .venv -r requirements-dev.txt
```

Скопируйте `env.example` в `.env` и заполните токены. Затем — бот и API в двух терминалах:

```bash
.venv/bin/python bot.py
```

```bash
APP_ENV=dev .venv/bin/uvicorn api.main:app --reload --port 8000
```

`APP_ENV=dev` разрешает заголовок `X-Dev-User-Id` вместо подписи Telegram — без него
фронтенд, открытый в обычном браузере, получит 401.

Документация API: http://localhost:8000/docs

## Тесты

```bash
.venv/bin/python -m pytest
```

## Деплой

Пуш в `main` — и GitHub Actions собирает стек на сервере. Наружу торчит только Caddy:
он держит TLS, отдаёт `/api` бэкенду, остальное — фронту. Адрес мини-аппа берётся
из `WEBAPP_URL`; домен покупать не нужно, подойдёт имя вида `109-71-246-174.sslip.io`.
Фронтенд деплоится своим воркфлоу из [protein_web](https://github.com/SanyCska/protein_web).

Подробности, секреты и порядок первого запуска — [DEPLOY.md](DEPLOY.md).

Локально стек поднимается так же:

```bash
docker compose up -d --build bot api
```

## Как считаются числа

**Дневная норма** — Mifflin–St Jeor: BMR × коэффициент активности × поправка на цель
(снижение −15%, поддержание 0, набор +12%). Белок 1.8–2.0 г/кг, жиры 0.9 г/кг,
углеводы — остаток бюджета. Норму калорий можно задать вручную (`calories_override`):
она заменяет только калории, белок и жиры остаются привязаны к весу, разницу
забирают углеводы — иначе при ручном урезании первым просел бы белок.

**Расход на нагрузке** — MET × вес × часы. В бюджет калорий не входит: норма сравнивается
со съеденным, а расход показывается отдельной строкой в ленте дня и своим графиком
в прогрессе. Вычитать его значило бы поднимать дневную норму за каждую тренировку —
и заодно считать активность дважды, ведь коэффициент активности уже описывает обычный день.

**Микронутриенты** — 25 позиций в `api/nutrition/catalog.py`. У блюда они появляются
при ИИ-разборе, а для продуктов их можно оценить отдельно: `POST /api/ai/product`
до сохранения и `POST /api/products/estimate` для всех сохранённых без состава.
Состав можно и снять с упаковки: `POST /api/ai/label` читает таблицу пищевой ценности
по фото, `POST /api/ai/supplement-label` — состав банки с витаминами (обычно это сразу
несколько веществ, они сохраняются одним `POST /api/supplements/bulk`). Дозы с банки
отдаются ровно как напечатаны, вместе с `serving` — на сколько капсул они посчитаны.

Так же они и хранятся: `dose` — как на этикетке, `label_serving` — на сколько единиц приёма
она посчитана, `taken_serving` — сколько принимает пользователь. В отчёт идёт
`effective_dose` = `dose` × `taken_serving` / `label_serving`: таблица на банке бывает дана
на три таблетки, а пьют одну.

Банка хранится как несколько веществ с общим `group_name` — названием, которое ввёл
пользователь. В списке добавок и в ленте дня это одна запись, а в отчёт по микронутриентам
каждое вещество попадает своей строкой; удаляется банка целиком через
`POST /api/supplements/bulk-delete`.
Оценка идёт от названия и КБЖУ, хранится за порцию продукта. Чтобы отчёт не выглядел
страшнее правды, он показывает «покрытие данными» — долю записей, у которых состав известен.

**Рекомендации «что добрать»** — детерминированные, без ИИ: нутриенты с покрытием ниже 80%,
отсортированные по дефициту, со списком продуктов-источников из `api/nutrition/sources.py`.

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | токен бота; им же проверяется подпись initData |
| `OPENAI_API_KEY` | для ИИ | без него ИИ-разбор отдаёт 503, остальное работает |
| `OPENAI_MODEL` | нет | по умолчанию `gpt-4o-mini` |
| `TZ` | нет | какой день считать сегодняшним, по умолчанию UTC |
| `PROTEIN_DB_PATH` | нет | путь к SQLite |
| `WEBAPP_URL` | для мини-аппа | https-адрес мини-аппа; без него нет ни кнопки, ни TLS-прокси |
| `MINIAPP_HOST` | в проде | хост для Caddy, деплой выводит его из `WEBAPP_URL` |
| `WEBAPP_ORIGINS` | нет | разрешённые origin'ы для CORS; по умолчанию берётся `WEBAPP_URL` |
| `APP_ENV` | нет | `dev` включает заголовок `X-Dev-User-Id` |
